# 充电平台核心架构基线

## 目标与边界

交付包括 C++17 / Qt 6.5.3 Widgets 用户端与管理端、保留的 Web 客户端和运营大屏、统一 FastAPI 服务，以及已训练的历史负荷预测。Qt 当前范围、真实数据映射与验收见 docs/QT_MIGRATION.md，预测口径见 docs/LOAD_FORECAST.md。

## 系统形态

采用“模块化单体 + 单一数据库”作为当前最小架构：

```text
 Qt Widgets 用户端 / Qt Widgets 管理端 / Web 页面与运营大屏
                    │
          REST 命令与查询 + WebSocket 事件
                    │
              FastAPI 模块化单体
      ┌─────────────┼─────────────┐
      身份认证       充电领域       事件投递
      └─────────────┼─────────────┘
                    │
       PostgreSQL（唯一业务事实来源）
```

Qt 客户端已使用 SQLite 保存偏好及按服务和身份隔离的只读快照。缓存中的余额、订单和电桩状态只用于带时间戳的离线查看，不参与离线交易或状态变更；PostgreSQL 始终是业务事实来源。

## 核心决策

1. **服务端权威**：客户端不提交可信的用户 ID、费用、电量或订单状态；服务端从 JWT 和数据库推导这些值。
2. **数据库守住并发不变量**：预约在一个事务内锁定用户与电桩；两个部分唯一索引分别禁止“一个用户有多个活动订单”和“一个电桩被多个活动订单占用”。应用检查改善报错，数据库约束负责最终兜底。
3. **显式状态机**：订单只允许 `reserved → charging → pending_payment → completed`，或从 `reserved` 进入 `cancelled`。停充生成不可变账单并释放电桩；用户确认付款后才扣款并完成。一个用户最多有一个预约、充电中或待支付订单；待支付不占桩。完成和取消均为终态。
4. **按时间推导计费**：充电量由服务端保存的开始时间、功率和演示倍率推导，不依赖进程内每秒累加器。进程重启后无需恢复定时器状态。
5. **预付费不欠费**：预约需要最低余额；可用余额（总余额减冻结金额）耗尽时自动停充。待支付账单与待审核提现分别冻结资金，付款或审核时在同一事务内释放冻结并记账，钱包余额永不为负。
6. **幂等资金与命令**：充值和预约携带幂等键；重试不会重复入账或重复创建订单。
7. **事务事件箱**：业务变更与事件在同一事务写入 `domain_event`。WebSocket 按游标读取，可断线续传；当前实现不承诺在线即达，客户端重连后仍能补读。
8. **认证边界**：开发环境用可替换的模拟验证码，成功后签发短期 JWT；管理员使用独立凭据和角色。生产环境必须接入真实短信提供商并更换密钥。

## 部署与演进

当前 API、自动停充协调器和事件投递运行在同一进程，数据库仍是唯一状态源。若以后扩容，可把协调器拆成 worker；行锁和终态检查保证重复处理不会重复结算。若事件量增大，可在不改变业务事务边界的前提下把事件箱转发到消息队列。

课程演示使用隔离目录中的本地 PostgreSQL 14，并使用独立 schema `charging_core`。数据库 URL 与 JWT 密钥只从被忽略的环境文件读取，不写入发布源码。移动端地图使用 OpenStreetMap 瓦片；UrbanEV 派生站点、充电枪和典型日聚合均先进入 PostgreSQL，再由公开只读 API 提供给前端。

## 本阶段验收

- 开发验证码登录并获得 JWT；
- 充值后余额与账本同时更新；
- 用户资料、钱包流水与历史订单可查询；
- 预约、开始、查询、手动停止、确认付款形成闭环；
- 并发预约由数据库约束阻止冲突；
- 预约超时释放电桩，余额耗尽自动停充并生成待支付账单；
- 管理员可维护用户、站点和电桩并留下运维审计；
- 管理员可查询订单、设备概况与分日营收；
- 用户和管理员 WebSocket 均能按事件游标推送并恢复；
- OpenAPI 文档可直接演示上述 REST 接口。

## 管理员控制台扩展（migration 4）

`console_routes.py` / `console_service.py` 在原管理接口上补充用户资料与删除、设备参数编辑、调账、账本、代预约、启停、退款和运营设置。`TransactionPool` 将现有 ChargingService 绑定到外层事务连接，内部事务使用 PostgreSQL savepoint，从而让管理订单命令与 ops_log 原子提交。钱包账本新增 adjustment/refund 两种类型，退款累计不超过已完成订单结算金额；用户余额和活动订单约束保持不变。

`/auth/console` 仅在 development 环境及显式 admin_console_enabled 开关开启时签发独立模拟管理员账号的令牌，默认关闭。原 demo_admin 只读权限保持不变。`console_settings` 不参与计费。详细验收与视觉数据口径以 `docs/ADMIN_CONSOLE.md` 为准。

## 作业闭环补齐（migration 5）

- 计费统一由 `billing.meter` 计算。北京时间分段覆盖 0–24 点，电费与服务费分别配置。预约保存价格快照，跨段按真实墙钟拆分，演示倍率只改变电量；调价不影响已预约订单。
- 车辆资料、模拟 SOC、充电上限和 PNG 头像保存 PostgreSQL，随账户跨客户端同步；车牌唯一，存在未完成订单时禁止修改车辆。车辆电量仍为作业模拟数据。
- 提现采用用户选定的演示闭环：申请 → 管理员审核 → 模拟到账或驳回。申请冻结金额，通过记 withdrawal 流水，驳回解冻；不接真实银行。
- 个人账单统计按北京时间付款日期读取全量个人已支付订单，支持当月和全部历史。历史数据旧订单使用结束时间兼容。
- 地址解析由服务端代理 Nominatim，路线由 OSRM 生成，在 Qt 地图绘制路线和道路步骤。显式查询限速、缓存；失败时用户可选城市或地图位置。UrbanEV 缺失的地址不伪造，经管理员核验后保存。
- 网页预览的设备定位需用户明确点击同意，共享坐标只供当前公开演示使用；服务端发布窗口 60 秒，Qt 本地保存上次位置。运行环境无法定位时提供城市、地址和地图选点。
- 具体入口、验收和环境限制见 `docs/QT_COMPLETION_20260908.md`。可执行资金与计费约束以 `scripts/check_qt_completion.py` 为回归入口。
