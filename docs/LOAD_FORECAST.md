# 负荷预测：同期模拟与历史实验

## 当前 Qt 管理端：历史同期模拟

2026-09-10 整合 admin-local 后，默认 `GET /admin/console/forecast?scope=business` 从数据库读取历史观测，按北京时间的月日映射目标日。支持数据库中的业务站点及全网，去重站点对应区域。完整性检查、短历史策略、Linux 导入与验证见 [整合说明](INTEGRATION_LINUX.md)。计算只使用目标日前连续完整历史；缺失数据不压缩日期，缺少昨日完整观测时返回 `available:false`。最近最多七天的误差属于验证期，不是独立测试结果；没有验证样本时指标为 null。3–8 月和闰日无对应日期。

## 保留的打包历史实验（Web 页面）

管理员入口：`/ui/admin.html#forecast`。页面可切换全网、12 个业务站点对应区域及其合计（底层训练产物覆盖 275 个区域），展示最近 48 小时、未来 24 小时、经验误差范围、峰值、历史高负荷阈值以及三种方法对比。数据截止 2023-02-28 23:00，预测日期是 2023-03-01，**不是当前实时预测**。

## 数据与训练是否有意义

已使用本项目数据库 `urbanev_observation.energy_kwh` 实际训练岭回归。数据为 275 区域 × 4,344 小时，共 1,194,600 条；演示订单没有混入训练。原始字段对应 UrbanEV 的 `volume.csv`，是额定功率等推导的小时电量，可能高估实际电量。区域观测不等于单站电表遥测。

这份数据适合验证周期性、区域差异、预测接口与评估流程；只有六个月、单城市历史，不能证明跨城市泛化或当前生产效果。源数据预处理包含缺失填补，可能有非因果信息；应用层时间划分不能消除源数据已发生的预处理泄漏。应把结果作为该公开数据版本上的历史实验。下一步优先引入更新的实测电量和更长时间跨度，再考虑复杂模型。

来源：[UrbanEV 官方仓库](https://github.com/IntelligentSystemsLab/UrbanEV)。固定源提交及数据库数值 SHA256 随结果保存。

## 方法与时间边界

- 训练期：2022-09-01 至 2023-01-17；前七天只提供滞后输入。
- 验证期：2023-01-18 至 2023-01-31；按各范围 MAE 在昨日、上周、岭回归中选择，且仅使用验证误差校准经验范围。
- 留出测试：2023-02-01 至 2023-02-28。测试前用训练和验证历史重新拟合，测试期间参数不更新；每日零点预测全天，前一天观测可作为下一日输入。这是滚动起点的 24 小时预测，不是一次预测整月。
- 最终展示：选用方法固定，再用全部历史拟合岭回归，生成 2023-03-01 的 24 小时结果。
- 特征：过去七天同小时电量、昨日均值、小时和星期的正余弦编码、截距。按训练期均值缩放；固定 Ridge alpha=1，不使用天气、未来价格或当日真实目标。
- 每个区域和全网分别拟合；全网预测不强制等于各区域预测之和。
- 阴影是验证期绝对误差 90% 分位数形成的对称经验范围，下限截断为零；不宣称严格概率置信区间。校准后重新拟合可能改变覆盖率，因此另显示测试覆盖率。
- 历史 95% 分位数用于描述高需求时段，不代表设备或电网容量。数据库缺少相应额定总功率，不能以桩数量替代容量告警阈值。

## 实际结果

| 方法 | 全网测试 MAE（kWh） | RMSE（kWh） | WAPE |
| --- | ---: | ---: | ---: |
| 昨日同小时 | 4238.725 | 5857.040 | 6.260% |
| 上周同小时 | 6944.673 | 9953.196 | 10.257% |
| 岭回归 | 4099.531 | 5416.883 | 6.055% |

WAPE = 绝对误差总和 / 实际电量总和 × 100%；不能读成逐点“准确率”。全网最终选择昨日同小时：其验证 MAE 低于岭回归，不能观察测试成绩后改选。全网测试经验范围覆盖率为 91.96%。275 个区域中 99 个选用岭回归、176 个选用昨日基线；这是验证集选择分布，不代表 99 个区域在测试期均胜出。全网岭回归相对昨日基线的 WAPE 降低约 0.205 个百分点，提升有限，尚未检验统计显著性。

## 复现与接口

```bash
.venv/bin/python -m pip install -e '.[forecast]'
.venv/bin/python scripts/train_load_forecast.py
.venv/bin/python scripts/check_load_forecast.py
node scripts/check_forecast_browser.cjs
bash scripts/public_tmux.sh restart
```

训练只读数据库，要求完整连续、非负、有限值区域小时矩阵，不默默填零。当前 NumPy 版本记录在产物 metadata。局部连接关闭 PostgreSQL JIT，以适配现有打包数据库运行库。产物位于 `src/charging_core/data/load_forecast.json` 和 `load_forecast_weights.npz`；后者保存全部范围最终岭回归系数、缩放值、选择标记与区域编号。结果缓存于服务进程，重训后重启服务生效。线上请求不执行训练，也无需安装 NumPy。

`GET /admin/console/forecast?mode=artifact&scope=all` 或 `scope=station-来源站点编号`，需要管理员令牌。返回数据口径、划分日期、区域目录、历史、预测、上下界、指标及选用模型。未知站点 404，非法参数 422，未登录 401，只读演示角色 403；缺少产物返回 `ready:false`。前端含加载、错误重试及过期请求保护。

验收覆盖：未来目标扰动不改变当日预测、系数和缩放；严格时间划分；276 个训练范围结果完整；仅按验证指标选择；接口权限及非法区域；页面直达、区域切换、响应式和返回导航。测试结果见 `deliverables/evidence/forecast-*`。
